# Saint-Island_Patent_MDS

**Saint-Island Patent Mistake Detection System** 以人工斷點方式逐階段開發。每一階段完成後停止，不在人工驗收前進入下一階段。

## 階段一：唯讀 DOCX 拆解與統一資料模型

狀態：已通過合成 TIPO 相容文件人工驗收；真實公司 DOCX 待取得後再補做驗證。

本階段範圍：

- 直接讀取 DOCX/OOXML，不修改來源文件。
- 保留原始段落文字與 Word run 字元位置。
- 另存正規化文字供後續規則檢核。
- 辨識標準專利章節、表格內段落與內嵌圖片清單。
- 產生 JSON 與 HTML 人工檢核報告。

人工斷點一驗收項目：

1. 發明／新型名稱是否正確。
2. 摘要、技術領域、先前技術、發明／新型內容、圖式簡單說明、符號說明、實施方式及申請專利範圍是否正確拆分。
3. 表格內的文字是否出現在正確章節。
4. Word 內嵌圖片數量是否正確。
5. 「尚未歸類的段落」是否包含原本應歸類的內容。
6. 中文、全形數字、英文及 prime mark 正規化後是否失真。

執行方式：雙擊專案根目錄的 `Check_Patent_DOCX_Stage1.bat`，選擇一份 `.docx`，再開啟 `output/patent_review_stage1` 內的 HTML 報告。

此階段明確不包含：錯誤規則、法律判斷、YOLO 圖式辨識、文字修改、DOCX 寫回及公司離線更新包。

## 階段二：文字規則引擎與問題定位

狀態：人工斷點二已通過；已依回饋取消全形冒號偵錯，準備進入階段三。

目前輸出統一的問題資料：規則編號、嚴重度、章節、段落、原文字元範圍、Word run、說明、建議及是否能安全自動修正。

原有人工斷點二啟用 12 條確定性規則，後續步驟 C 擴充後共 22 條；全形冒號仍視為合法，不列入偵錯。

- 必要章節缺漏、空白或重複。
- 符號說明格式、同號異名，以及代表圖符號與完整符號表的缺漏或名稱不一致；半形與全形冒號皆視為合法分隔符號。
- 請求項編號缺漏、不連續，以及無效或指向後項的依附關係。
- 全形英數字與非標準 prime mark；只提供安全替換候選，不會直接修改 Word。

人工斷點二驗收方式：

1. 雙擊專案根目錄的 `Check_Patent_DOCX_Stage2.bat`，選擇一份 `.docx`。
2. 開啟 `output/patent_review_stage2` 內的 HTML 報告。
3. 確認問題嚴重度、章節、原文紅色範圍及修改建議是否合理。
4. 可另開啟 `output/patent_review_stage2/demo` 的刻意含錯報告，確認所有類型的顯示方式。

此階段明確不包含：法律結論、原始 Word 寫回、YOLO 圖式辨識及公司離線更新包。

### 階段一延伸：TIPO DOCX 相容性試驗

狀態：已完成官方輔助偵錯網站上傳與分頁驗證。

已由網站前端解析規則確認：

- DOCX 會先轉成 HTML，再組成智財局使用的 XML 節點。
- 中文／英文新型名稱的標題與內容必須位於同一個 Word 段落。
- 摘要標題必須使用 `【中文摘要】`，不能只寫 `【摘要】`。
- `【技術領域】`、`【先前技術】`、`【新型內容】`、`【實施方式】` 後必須緊接 Word 真正的編號清單，使轉換後成為 HTML `<ol>`。
- `【符號說明】`與`【代表圖之符號簡單說明】`採一行一組 `半形符號:文字`。
- 請求項採 `【請求項1】內容`、`【請求項2】內容`格式，以保留明確請求項編號。
- `【圖式簡單說明】`採單一編號段落；本合成樣本以 `0009` 統整圖1至圖5，並以段內換行分列。

官方驗證結果：

- 儀表板顯示 DOCX 已成功上傳。
- 摘要、技術領域、先前技術、新型內容、圖式簡單說明、實施方式及申請專利範圍均已建立對應頁面與段號。
- 圖式簡單說明後的實施方式由 `0010` 開始，確認圖式簡單說明只占用單一 `0009` 段號。
- 八項請求項均被辨識，其中請求項1為獨立項，請求項2至8為附屬項。

此相容性試驗只處理輸入文件結構，不代表已開始階段二的實體錯誤規則。

## 階段三：專利圖式與文件交叉比對

狀態：人工斷點三已通過；雙清單需求已納入 GUI 整合。

此階段先連接現有 OCR 結果與兩套文件清單：

- 「完整符號說明」與「代表圖符號說明」分開擷取、分開保存，絕不自動合併。
- OCR 頁預設使用完整符號說明；標號清單欄位提供按鍵切換代表圖符號說明。
- 兩套清單都轉成既有 OCR 格式 `{number, name}`，因此沿用相同的大小寫、prime mark 與排序規則。
- 使用者在 OCR 頁對兩套清單做的手動修改分別暫存，切換後不會互相覆蓋。
- 同號同名自動去重；同號異名、格式無法解析或英數混合區間具有歧義時，標記為必須人工確認。
- `1-5` 這類純數字區間可安全展開；`A-C` 或 `10A-10C` 不自行猜測。
- 低信心 OCR 標號仍視為「有偵測到」，但另列為待確認，不會直接被當成漏辨識。
- 只有文件標號在全部圖片都沒出現時，才列為整體缺漏；單一圖片沒出現只顯示差異，不直接判定錯誤。
- 圖片出現但目前選定文件清單未列的標號，列為待使用者確認，不自動刪除。

人工斷點三不包含：Word 寫回、法律判斷、從文字名稱推測圖片元件，以及自動判斷哪一頁必然是代表圖。

## 階段四：GUI 原文錯誤定位

狀態：GUI 基本流程與原文錯誤定位視窗完成，等待人工斷點四驗收。

目前已完成：

- 首頁新增「專利文件偵錯」功能入口。
- 選擇 DOCX 後執行文字規則、顯示錯誤／警告／提示與來源位置。
- 以兩個分頁顯示完整符號說明與代表圖符號說明，兩者皆可人工修改。
- 有效清單會自動暫存到 OCR 頁；按下確認按鍵後重新驗證人工內容並直接前往 OCR 頁。
- OCR 頁可在兩套清單間切換，兩套人工草稿分開保存。
- 原始 DOCX 全程唯讀。
- 點選問題後只顯示錯誤規則／種類、章節、段落、字元範圍、Word run 與原始段落。
- 原始段落以紅色標出精確問題位置，方便使用者回到 Word 尋找。
- 介面不提供修訂欄位、採用／忽略狀態或修訂操作按鈕。

永久排除範圍：程式不建立修正版 Word、不覆蓋來源 Word，也不修改任何 DOCX／OOXML 節點；所有正式修訂均由使用者回到原始 Word 手動完成。

## 步驟 C：進階格式與交叉一致性檢核

狀態：程式、自動測試及人工斷點五均已通過。

本步驟新增 10 條規則：

- `PNO001`～`PNO003`：讀取 Word OOXML 自動編號，檢查說明書正文是否具有四位數段號、格式是否正確，以及是否由0001連續編排。
- `ORD001`：依現行專利說明書的一般結構提示章節順序異常；因個案可能有例外，列為警告並保留人工判斷。
- `FIG001`～`FIG002`：檢查圖式簡單說明的圖號順序，以及指定代表圖是否已列入圖式簡單說明。
- `REF001`～`REF002`：以保守文字比對提示內文標號未列入完整符號說明，或已知元件名稱與標號配對不一致。
- `CLM004`～`CLM005`：檢查多項附屬項是否採選擇式記載，以及是否直接或間接依附另一多項附屬項。

GUI 同步新增：

- OCR 頁頂部新增「← 回文件偵錯」，可直接返回專利文件偵錯頁，不必繞回首頁。
- 頁面切換不會清除目前已載入的 OCR 結果、人工修正或兩套符號清單草稿。

人工斷點五建議驗收項目：

1. 使用已通過官方網站檢核的合成 DOCX，確認新增規則仍為零問題。
2. 在 Word 故意刪除一個段號或改成跳號，確認能定位到原始段落。
3. 故意把圖2改成圖3、將正文元件名稱配上錯誤標號，確認只出現可理解的警告。
4. 建立非選擇式多項附屬項與「多項附屬項依附多項附屬項」案例，確認列為錯誤。
5. 從文件偵錯頁前往 OCR，再按「← 回文件偵錯」，確認可直接返回且資料未遺失。

本步驟仍只提供錯誤位置與種類，不寫回或輸出修正版 Word。規則結果是格式／一致性提示，不取代專利專業人員對個案的法律判斷。

## 步驟 D：拖放匯入

狀態：已完成程式與自動測試，進入人工斷點六驗收。

- 專利文件偵錯頁可從 Windows 檔案總管直接拖入一份 `.docx`，放在頁面內的表格、文字框、預覽區或空白處皆可。
- OCR 頁可直接拖入一份 `.pdf`，並沿用「選擇 PDF」按鈕相同的轉圖與載入流程。
- 副檔名不符、一次拖入多個檔案、非本機網址、資料夾或不存在的路徑都不會開始處理，並顯示原因。
- DOCX 頁不接受舊式 `.doc`，OCR 頁的拖放入口不接受圖片；原有「選擇多張圖片」按鈕仍可匯入 PNG、JPG、JPEG 與 BMP。
- 副檔名比對不分大小寫，因此 `.DOCX` 與 `.PDF` 亦可使用。

人工斷點六建議驗收項目：

1. 將一份 DOCX 拖到文件偵錯頁的不同區域，確認會直接擷取並顯示結果。
2. 將 PDF 或其他檔案拖到文件偵錯頁，確認顯示「僅接受 Word 文件（.docx）」且既有結果不被清除。
3. 將一份 PDF 拖到 OCR 頁，確認完成轉圖、顯示第一頁並可開始辨識。
4. 將 DOCX 或圖片拖到 OCR 頁，確認顯示「僅接受 PDF 文件（.pdf）」且既有 OCR 結果不被清除。
5. 一次拖入兩個檔案，確認程式要求重新選擇單一檔案。
