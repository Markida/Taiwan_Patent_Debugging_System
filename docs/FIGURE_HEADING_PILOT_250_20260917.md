## 「橫著的圖」與圖號真值

`figure_prefix_rotate_right` 表示原圖必須順時針轉 90° 才正向。
人工輸入的圖號永遠是轉正後的文字；不會把橫向的 6、9 等字形當成
另一個文字標籤。增強副本的應修正角度為：

`副本應修正角度 = (原圖應修正角度 − 副本已順時針旋轉角度) mod 360`

例如原圖需右旋 90°，四個副本的應修正角度依序為 90°、0°、270°、180°。
只有仍需右旋 90° 的副本使用第 3 類；圖號文字四版完全相同。

推論流程先根據圖字類別與圖題配對判斷方向，把圖號裁切轉正後做圖號 OCR，
再建立非破壞性的整頁轉正版，最後把轉正後的頁面交給元件標號辨識。
原始頁面不會被覆寫；不確定或方向證據互相衝突時仍保留人工確認。

## 訓練設定與安全限制

使用本機通用 COCO 預訓練 `models/pretrained/yolov8s.pt`，不沿用可能接觸過
同源專利頁面的元件定位模型。輸入 1536、batch 2、最多 40 epochs、patience 10，
禁用水平／垂直翻轉，以免改變文字語意。

本次明確使用 `--experimental --skip-test`；模型選擇只看驗證集，測試集留待
最後固定候選模型後評估。試訓練、資料副本、權重均留在獨立實驗目錄。
由於負頁、英文與 prime 圖號的覆蓋不足，正式門檻仍為未通過；不自動發布，
不覆寫現有正式模型。

可重用的工具：

- `python -m training.figure_heading.prepare_pilot_dataset --output <新實驗目錄>`
- `python -m training.figure_heading.train_figure_heading --experimental --skip-test ...`
- `python -m training.figure_heading.export_candidate --model <候選.pt> --imgsz 1536`
- `python -m training.figure_heading.evaluate_candidate --experimental --split val ...`
- `python -m training.figure_heading.evaluate_candidate --experimental --split test ...`

建立器拒絕覆寫既有實驗目錄；試訓練報告不能用來核准正式模型。

## 實驗啟用

候選 ONNX 以獨立名稱 `models/figure_heading_pilot_v1.onnx` 放入本機開發版，
並由 `figure_heading_pilot_v1.experimental.json` 驗證模型、類別檔與評估報告
雜湊。辨識頁只有在所有雜湊均吻合時才顯示且預設勾選「試用圖題自動轉正」；
取消勾選即可回退原流程。實驗清單不能通過正式模型的 release manifest
檢查，打包流程也不會把它誤當正式模型。

另以完整 `BatchRecognitionWorker` 實測一張預期需右轉 90° 的保留頁
`CP28293` 第 2 頁：程式實際套用 90°、方向信心 1.0，轉正後自動讀得
圖號 `2`，且後續 OCR 全程沒有錯誤。這項測試使用的不是單獨模型推論，
而是與辨識頁相同的「方向判斷 → 非破壞式轉正 → 圖號辨識」完整路徑。

本模型仍不是正式發布模型：資料只有 8 個負頁，且沒有英文或 prime 圖號，
尚未符合正式資料覆蓋門檻。

## 圖式辨識頁三步操作（2026-09-21）

辨識頁改成「第一步.自動旋轉 → 第二步.圖片標號辨識 → 第三步.辨識結果與
標號清單比對」。第一步在背景逐張分析圖題方向，只對方向證據足夠的頁面
另存 90°／180°／270° 轉正圖；不執行元件標號 OCR，也不覆蓋原圖。
第二步在轉正圖上辨識標號，不再重複旋轉；第一步的原圖與轉角會保留在結果
及本機保存紀錄中。方向證據不足的頁面維持原狀並提示人工核對。

以保留測試頁 `CP28293` 第 2 頁串跑兩步：第一步右轉 90°，第二步直接
讀取轉正圖、未再旋轉，並取得圖號 `2`。本機開發版可用此實驗模型試用；
公司正式更新包仍不夾帶尚未核准的實驗權重，會明確提示改用手動旋轉。
