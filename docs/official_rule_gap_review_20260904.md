# 官方規則對照與新增檢核建議（2026-09-04）

## 結論與範圍

本次僅進行唯讀研究，沒有新增、停用或更改任何檢核規則。

現有程式已涵蓋官方公開說明中的多數核心文字一致性檢查。下一步較值得補強的是：不依賴 OCR 的圖號引用完整性、請求項中「已使用」元件符號的括號、摘要長度提醒，以及重複請求項；再逐步增加請求項／說明書的對照證據，而不是直接以關鍵字作出專利有效性判斷。

這份報告區分三件事：

1. 官方公開文件可以確認的規範或功能。
2. 本專案程式中實際存在的檢核。
3. 為本專案提出的實作設計；這些設計不是智財局公布的演算法，也不是已驗證的法律判斷器。

本次只開啟官方線上系統入口一次，沒有登入、輸入驗證碼、上傳文件或批次測試。官方使用指南 PDF 超過瀏覽工具的大小上限，因此僅取得其公開搜尋索引摘要；沒有讀取到完整指南，更沒有取得網站所有內部規則。以下對「線上系統已有功能」的描述，僅限公開索引能證實的項目。[官方使用指南](https://tiponet.tipo.gov.tw/downloads/moduleP30/%E5%B0%88%E5%88%A9%E7%94%B3%E8%AB%8B%E6%96%87%E4%BB%B6%E8%BC%94%E5%8A%A9%E5%8A%9F%E8%83%BD%E4%BB%8B%E7%B4%B9%E8%88%87%E4%BD%BF%E7%94%A8%E6%8C%87%E5%8D%97.pdf)

## 實作前要保留的相容性

- 維持 `【1】`、`【01】`、`【0001】` 的現行接受方式，不重新啟用字型、字級、空白或分節符號嚴格檢查。
- 維持僅在實施方式、且符合使用者指定冠詞等條件時，才強制檢查元件後方標號。
- 名稱辨識採最長合法名稱；`第一PTC元件` 不切成 `PTC元件`，`第一主導引面` 與 `第一副導引面` 均合法時不互報錯字。
- 維持完整名稱保護、無標號元件白名單、元件括號補充文字、大小寫、英數混合、特殊符號及 prime 支援。
- `圖3A`、`圖3B` 是不同圖號；PDF 頁數不等於圖號。一頁多圖仍依人工確認映射。
- 請求項換行不能截斷內文；引用記載形式的另一獨立項不能被一律當成普通附屬項。
- 目前的字號、段號、單複數、標點等公司規則保持原樣；若其比官方原則更嚴或更寬，只在規則來源資料中區分，不趁這次優化偷偷變動。

另有一項既有技術落差應先建立回歸案例：`_drawing_issues` 所用圖號正規表示式仍以整數為主，可能將圖3A及圖3B當作同一個圖3；新增圖號檢核前應和段落圖式比對共用尾碼圖號解析器，避免同一份文件不同頁面判定不同。

## 建議第一批：低誤報且容易驗證

以下的例句均為本報告為說明測試條件所自擬，不是官方原文。

### A. 文字引用圖號存在性與圖說完整性

**優先級：P1。建議先提示，文件與圖號映射完整且經確認後才列錯誤。**

官方原則要求多幅圖式均有對應圖說；現有 OCR003 僅檢查「是否在任何位置被使用」，兩者不同。[審查基準第二篇第一章，1.2.5](https://www.tipo.gov.tw/tw/patents/998-66037.html)

實作設計：

1. 先建立三個集合：圖說宣告的圖號、本文引用的圖號、使用者確認的圖片映射圖號。
2. 沒有載入圖片也能檢查：本文引用 `圖9`，但完整圖說只列圖1～8。
3. 已確認圖片全集時，檢查每個圖號是否有圖說，不因它在實施方式被引用過就跳過。
4. 同一圖號的缺漏集中成一筆，列出所有來源位置；不要每個詞都產生一筆相同錯誤。

排除條件：先前技術中的他案圖號、引用文獻的圖號、未確認圖片全集、正在補圖的草稿、不能可靠拆解的圖號範圍。尾碼及範圍必須用現有統一解析器，不做 `int()` 截尾。

正例：圖說只有圖1、圖2，實施方式寫「參閱圖3」→ 提示缺少圖3的圖說。

反例：「日本公告案的圖3揭露……」→ 不和本案圖號清單比對。

風險：外部引用與本案引用範圍辨別不良；因此必須提供排除/本案圖號確認，不靠「看到圖字就比對」。

### B. 請求項已使用的元件符號應置於括號

**優先級：P1。精確匹配時可列錯誤，模糊候選不報。**

法規允許請求項引用圖式符號，並規定其位置及括號；這不是要求所有請求項元件都加符號。[專利法施行細則第19條第2項](https://law.moj.gov.tw/LawClass/LawSingle.aspx?flno=19&pcode=J0070008)

實作設計：

1. 只在請求項內尋找「完整合法元件名稱 + 完整已知符號」。
2. 找到符號時才檢查其括號；接受半形或全形圓括號。
3. 使用現有名稱最長匹配、prime 正規化及來源位置映射。
4. 若同處已有「名稱／符號錯配」，合併顯示，不再疊加括號警告。

正例：清單為 `10：基座`，請求項寫「該基座10」→ 提示使用 `(10)` 或 `（10）`。

反例：「該基座」→ 不要求加符號；「請求項10」→ 不是元件符號；「長度10mm」→ 技術數值，不是元件符號；「一PTC元件」→ `PTC` 不能被切為符號。

風險：`R1` 等名稱與符號重疊、數值巧合。必須同時具備確定名稱、確定符號及 token 邊界，不能只搜尋數字。

### C. 中文摘要超過250字提醒

**優先級：P1。提示/警告，不作一律不合格的錯誤。**

250字是原則性上限，不應被程式解讀成所有情況的硬性駁回條件。[專利法施行細則第21條第1項](https://law.moj.gov.tw/LawClass/LawSingle.aspx?flno=21&pcode=J0070008)

實作設計：只計算中文摘要內容，排除章節名稱、發明名稱、代表圖符號清單、欄位代碼與隱藏修訂內容。顯示實際計數與採用的算法。計數未有可確認的官方機器算法時，先同時顯示「非空白字元數」及「中文單字＋英文詞數」作估算，邊界案例不硬報錯。

正例：明確超過250個中文字的中文摘要 → 提醒濃縮。

反例：中文摘要不到250字，但加上英文摘要或代表圖說明後超出 → 不報。

風險：標點、英文字、化學式計數口徑不同；不要虛稱計數與官方線上系統完全相同。

### D. 完全重複的請求項／重複貼上的長片段

**優先級：P1。警告。**

官方審查原則包含請求項簡潔性；程式先做字面重複候選，不判斷實質權利範圍相同。[審查基準第二篇第一章，2.4.2](https://www.tipo.gov.tw/tw/patents/998-66037.html)

實作設計：

- 跨項比對只移除該項自己的項號、空白及等價排版符號；保留被引用的請求項次、否定詞、單位、數值、數量詞及 prime。
- 正規化全文 hash 相同時列出兩個項次，集中一筆提醒。
- 同一請求項的重複長片段可另列提示；初始門檻建議30字且非依附開頭，門檻屬工程設定，須用本案測試集調整。

正例：請求項7與8除自己的項號外完全相同 → 提示疑似重複。

反例：第7項依附請求項1、第8項依附請求項2，其餘相同 → 不以完全重複規則判錯；「一元件」與「二元件」也不能被正規化成相同。

風險：看似相近不等於同範疇同範圍；第一版不使用相似度分數直接指控重複。

## 建議第二批：證據型、需人工判斷

### E. 請求項技術特徵的說明書支持線索

**優先級：P2。只顯示待確認，不能顯示「不受說明書支持」定論。**

官方要求支持性，但支持性不是逐字匹配；本功能僅用來提示可能遺漏的文字證據。[審查基準第二篇第一章，2.4.3](https://www.tipo.gov.tw/tw/patents/998-66037.html)

實作設計：重用現有元件/冠詞解析結果，建立「請求項→元件、特徵短語→說明書段號」反向索引。找不到時顯示該詞的候選段落與「未找到直接文字對應」，讓使用者確認上位/下位詞、同義詞或圖式是否能說明。摘要和符號表不能單獨被算成詳細技術說明證據。

正例：請求項新增「一防水膜」，說明書正文完全找不到名稱或已確認別名 → 提醒人工查核。

反例：請求項「固定件」，實施方式詳細說明「螺栓」且公司詞典已確認上下位關係 → 不直接報錯。

風險：同義詞、總括、通常知識及圖式揭露無法只靠字詞判斷。先提供證據面板，不上自動法律結論，也不為了覆蓋率把所有不存在符號表的名詞都報錯。

### F. 選用式範圍用語的低干擾提醒

**優先級：P2。預設關閉或列人工確認。**

部分「較佳為、例如」等用法有明確性風險，但並非出現就違規。[審查基準第二篇第一章，2.4.1.5(5)](https://www.tipo.gov.tw/tw/patents/998-66037.html)

實作設計：只有同一請求項、同一參數附近同時出現兩個範圍及「較佳為／最佳為」時才生成候選，並顯示完整句子。另可把摘要中明顯行銷詞作單獨提示，其詞表須由公司核定；不把「改善、提升效率」這類技術功效一律算廣告。[專利法施行細則第21條第2項](https://law.moj.gov.tw/LawClass/LawSingle.aspx?flno=21&pcode=J0070008)

正例：「厚度為1至5mm，較佳為2至3mm」→ 待確認是不是想保留兩個範圍。

反例：實施方式使用「較佳」；元件名稱中的「等距」；已有明確定義的相對術語；「該等元件」→ 不報。

風險：合法表達很多，不能把「等、約、至少、包含、具有」加入全局黑名單。

### G. 數值範圍矛盾及封閉式附屬項提醒

**優先級：P2，限高可信範圍。簡單數值矛盾可列錯誤，其餘警告。**

相關官方討論包括特徵不正確、開放／封閉式連接詞；是否封閉仍須辨識實際語境。[審查基準第二篇第一章，2.4.1.3.1及2.3.3](https://www.tipo.gov.tw/tw/patents/998-66037.html)

實作設計：

- 第一版只處理同一已確認參數、同一單位、明確區間的上下限倒置，例如「長度為8至3mm」。
- 有清楚依附關係且單位可換算時，可提示附屬項所加範圍與上位項不相交。
- 只有明確「僅由A與B組成」且同一組合層級時，才提示附屬項又增加C；半開放式及一般「具有」不自動判封閉。

反例：反應從80度降至30度是過程，不是倒置範圍；不同實施例、不同參數、量測容差、引用記載的獨立項，不互相比對。

風險：此功能容易涉及技術解釋；先不做全文章節所有數字交叉比對，也不把沒有冠詞的普通數字當元件標號。

### H. 請求項內插圖與僅靠圖號界定的提示

**優先級：P2。待確認。**

法規對請求項插圖、僅用圖式／頁行界定技術特徵有所限制，同時保留必要情況及化學式、數學式。[專利法施行細則第19條第1、3項](https://law.moj.gov.tw/LawClass/LawSingle.aspx?flno=19&pcode=J0070008)

實作設計：利用 DOCX 已有的內嵌物件來源位置，標示落在請求項內的非公式圖片；對「如圖X所示之形狀」等短語只顯示人工確認入口，檢查是否尚有足夠文字特徵。必要時提供「這是公式／化學式」確認旗標。

反例：OMML公式、化學結構、單純括號參考符號、請求項外的圖式不報；遇到不能區分公式截圖與插圖者不得直接列錯誤。

風險：DOCX 圖片並不必然是禁止的插圖，單一引用短語也不能證明整項缺乏文字界定。

## 新型、發明與法律判斷邊界

施行細則第45條將相關第13至23條準用於新型，但不能因此把發明實體審查的全部結論直接套成新型的自動錯誤。第一批可共用文字／格式一致性檢查；支持性與明確性等第二批僅作寫作輔助。[專利法施行細則第45條](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=J0070008)

不建議本階段增加自動判斷：新穎性、進步性、單一性、可據以實現、新事項、優先權成立或可否獲准專利。這些需要外部證據、完整申請歷程或專業技術判斷，不能把關鍵字規則包裝成確定結論。

另須注意「公開法規」與「公司接受格式」不是同一件事。例如官方段號條文的寫法，與使用者已要求接受的短段號屬不同設定層；本次不更動公司設定，更不聲稱所有公司格式均已通過官方送件驗證。[專利法施行細則第17條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?flno=17&pcode=J0070008)

## 建議落地順序與驗收

1. 先完成效能優化，固定一份「現行輸出基準」；相同文件的既有規則ID、嚴重度、來源位置、例外與文字內容不得因優化改變。
2. 建立共用分析索引：段號、圖號、請求項依附圖、合法元件名稱、符號、白名單，一份文件只計算一次；各新增規則讀取索引。
3. 第一批 A～D 以獨立規則 ID、獨立開關加入；先只產生影子報告，不混入日常錯誤列表。
4. 使用者審核命中案例後，再決定各規則正式嚴重度。不得以測試通過推論法律上必定正確。
5. 每條至少包含：正常例、真正缺失、曾經造成誤報的反例、跨段請求項、表格、prime、圖3A/3B、元件重疊、本文件白名單，以及「同一問題只報一次」。
6. 第二批 E～H 等第一批誤報與漏報率可量測後再做；保留原文證據與排除原因，讓使用者可核對。

性能設計：新規則只用本地內容，不在開啟文件或每次點選錯誤時連網；法規來源更新另行人工維護。大型比對在背景執行、可取消，舊文件結果不得回寫到新文件的畫面。
