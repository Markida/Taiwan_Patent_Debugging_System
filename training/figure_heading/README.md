# 「圖＋完整圖號」與頁面方向辨識

這是一條獨立於既有元件標號 OCR 的訓練流程。舊人工標註曾刻意省略
圖題中的數字／英文，因此舊模型應繼續只負責元件標號，不能拿來尋找
圖題圖號。

新模型共有三類：

- figure_prefix：只框作為圖題開頭、目前不需要右旋 90° 的單一「圖」字。
- figure_identifier：把其後完整圖號框成一組，例如 1、3A、1'。
- figure_prefix_rotate_right（工具顯示「橫著的圖（右旋90°）」）：若整頁
  需要向右旋轉 90° 才會正向，就用此類別框圖題開頭的單一「圖」字。

每個 figure_identifier 框還會保存實際圖號文字、原始文字層種子值與
配對編號。文字本身不會當成定位模型的輸入；配對編號則用來確保旋轉
增強後的新類別仍對應正確圖題，並驗證辨識出的圖號是否真的正確。
缺少文字或配對不完整的頁面不能標記為完成。

不要把「立體圖、前視圖、圖式、圖例、附圖」中的「圖」當成
figure_prefix。沒有圖題的頁面也要確認完成，作為負頁。

## 人工複核

雙擊專案根目錄的 Annotate_Figure_Headings.bat。

每個真正的圖題都必須有一個「圖」框與一個相鄰的「圖號」框。快捷鍵：

- Alt+1：切換到「圖」。
- Alt+2：切換到「圖號」（數字鍵仍可輸入圖號文字）。
- Alt+3：切換到「橫著的圖（右旋90°）」。
- Delete：刪除錯框。
- Ctrl+S：儲存草稿。
- Ctrl+Enter：確認本頁並到下一頁。

## 建立正式 YOLO 資料

完成全部 501 頁後，雙擊 Build_Figure_Heading_Dataset.bat。

產生器會拒絕不完整或配對錯誤的頁面，並要求：

- 至少 400 組人工確認圖題（每組仍是一個圖字框加一個圖號框）。
- 至少 100 張人工確認的無圖題負頁。
- validation 與 test 各至少 20 組圖題、5 張負頁。
- validation 與 test 各至少來自 5 份不同來源文件。
- 全資料集至少 20 組含英文字母、10 組含 prime、5 組純英文圖號；
  validation 與 test 也各自至少要含這三種稀有型態。
- 每頁「圖」與「圖號」框數相等且可通過幾何配對。
- 未知類別、過小框、缺文字或重複共用配對編號都會立即停止建置，
  不會被靜默當成負頁。
- 同一來源文件及相同影像內容不得跨 train／validation／test。

資料會機械產生 0／90／180／270 度四方向版本，但仍留在原本的文件級
split，避免同一文件洩漏到不同集合。

為避免舊檔混入，若輸出資料夾已存在，建立器會停止而不覆寫；請指定
新的 --output 路徑保存下一版資料。

## 訓練與程式啟用

在有 GPU 的 patent_ai 環境雙擊 Train_Figure_Heading.bat。

只有資料報告通過正式門檻才會開始訓練。完成後先輸出不會被程式
自動載入的候選檔：

- training/figure_heading/candidates/figure_heading_locator_v1.pt
- training/figure_heading/candidates/figure_heading_locator_v1.onnx
- training/figure_heading/candidates/figure_heading_locator_v1.names.json
- training/figure_heading/candidates/figure_heading_locator_v1_metrics.json

訓練後依序雙擊：

1. Evaluate_Figure_Heading_Candidate.bat：只用凍結 test 檢查圖號集合、
   自動頁面映射、方向判斷及負頁誤報；含英文／prime 的稀有圖號另有
   獨立樣本數、來源數與正確率門檻，不會被大量純數字結果稀釋。
2. Approve_Figure_Heading_Candidate.bat：只有前一步全部達標時才會明確
   核准，將 ONNX 與核准清單發布到 models。

程式自動載入前會再次核對核准清單、三個類別名稱及模型 SHA-256；
缺清單、未核准或檔案曾被更動，都會保持此功能停用。
端到端發布門檻有不可調低的安全線，並同時計算唯一正／負頁與正／負
來源文件數；正式發布步驟會重算報告是否真的達標，而不是只相信報告
中的通過旗標。

程式啟動辨識時會自動尋找上述模型，不增加操作員設定。偵測出的
「圖→圖號」方向對應需要施加的順時針修正角度：

- 向右：0°（正向）
- 向下：270°（左旋 90°）
- 向左：180°
- 向上：90°（右旋 90°）

只有完整、高信心且整頁投票一致時才會自動設定圖號或建立非破壞性
轉正版。「橫著的圖」達高信心時，即使圖號 OCR 尚未成功，也會要求
向右旋轉 90°；若它與其他明確方向證據衝突則不自動旋轉。不確定時
保留原圖與人工欄位。圖題內的圖號會從一般元件標號結果排除，避免
後續段落比對誤把它當成元件。
